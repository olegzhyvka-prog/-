# Unit Economics Calculator

## Правило номер один
**Ти НЕ рахуєш ці числа в голові і не пишеш їх з пам'яті.** Ти запускаєш скрипт.
Арифметика в тексті — джерело помилок, які потім коштують реальних грошей.
Запусти → покажи вивід → інтерпретуй.

---

## Скрипт 1 — економіка моделі

```bash
python3 scripts/unit_economics.py \
  --price 19 --margin 0.75 --retention 8 \
  --cpc 2.4 --cr-landing 0.03 --cr-trial 0.25 \
  --fixed 500 --cogs 3
```

| Прапорець | Що це | Де взяти |
|---|---|---|
| `--price` | ціна/міс або чек | твоя гіпотеза |
| `--margin` | валова маржа часткою | цифрове ~0.8-0.9, з людьми ~0.4-0.6 |
| `--retention` | скільки місяців живе клієнт | **найчастіше завищують** — див. нижче |
| `--cpc` | вартість кліка | Semrush MCP `keyword_research`, або факт з кабінету |
| `--cr-landing` | CR лендінга в лід/тріал | бенчмарк 2-5% холодний трафік |
| `--cr-trial` | CR ліда в оплату | B2C 10-25%, B2B 5-15% |
| `--fixed` | постійні витрати/міс | хостинг, підписки, зарплати |
| `--cogs` | змінна собівартість на юзера | **AI-токени, API, підтримка** |
| `--one-time` | разова покупка, не підписка | |

### Що робити з виводом

Головний рядок — не LTV:CAC, а **«МОДЕЛЬ ЛАМАЄТЬСЯ ЯКЩО»**.
Це два числа, які перетворюють абстрактну ідею на перевірюване твердження:

```
CPC піднімається вище    $0.22
CR лендінга падає нижче   32.00%
```

Далі береш реальний CPC у ніші і реальний бенчмарк CR і порівнюєш.
У прикладі вище: потрібен CR 32% на холодному трафіку — це неможливо.
Гіпотезу вбито за 4 секунди, до того як написано перший рядок коду.

### Три найчастіші помилки на вході

1. **Завищений `--retention`.** Люди пишуть 12-24 міс бо «підписка ж».
   Реальність для нового продукту без ретеншн-механіки: 2-4 місяці.
   Якщо немає своїх даних — став 3 і подивись чи виживає модель. Виживає — добре.
2. **`--cogs 0` для AI-продукту.** Рахуй **найважчі 10% користувачів**, не середнього.
   Підписка $20 і важкий юзер на $35 токенів = від'ємна маржа на найактивніших.
3. **Забутий `--cr-trial`.** CR лендінга 3% ≠ 3% платників. Помилка у 4-10 разів
   у найважливішому числі досьє.

### Сценарії
Прогоняй завжди три, не один:
```bash
# песимістичний: retention/2, CPC×1.5, CR/1.5
# базовий:       твої оцінки
# оптимістичний: те що ти хочеш побачити
```
Приймай рішення за **песимістичним**. Якщо він виживає — гіпотеза сильна.

## Скрипт 2 — розмір вибірки і читання результату

### До запуску: скільки треба трафіку
```bash
python3 scripts/sample_size.py size --baseline 0.02 --lift 0.30
```
Це число йде в блок 8 досьє (kill-критерії). Без нього ти читатимеш шум.

### До запуску: що взагалі можна побачити на наявному бюджеті
```bash
python3 scripts/sample_size.py mde --baseline 0.02 --n 1500
```
Найкорисніша команда в усьому наборі. Часто відповідь: «на цьому трафіку
ти побачиш тільки різницю +85%». Тоді тестувати колір кнопки безглуздо —
тестуй радикально різні офери.

### Після запуску: чи це реальний результат
```bash
python3 scripts/sample_size.py read --a 12 900 --b 21 950
```
Дає p-value і довірчий інтервал. Якщо інтервал перетинає нуль —
ти навіть не знаєш у який бік працює зміна.

## Як інтерпретувати (шпаргалка)

| LTV:CAC | Що це означає | Дія |
|---|---|---|
| < 1 | Кожен клієнт — збиток | Вбити або змінити модель |
| 1-3 | Виживання без прибутку, нуль запасу | Не масштабувати. Полагодити важіль |
| 3-5 | Здорово | Масштабувати обережно |
| > 5 | Або відмінно, або ти недоінвестуєш у зростання | Підняти бюджет і подивитись де зламається |

| Окупність | Наслідок для кешу |
|---|---|
| < 3 міс | Можна реінвестувати агресивно |
| 3-12 міс | Норма для SaaS, але потрібен запас кешу |
| > 12 міс | Потрібне зовнішнє фінансування. Для соло-фаундера — стоп |

**Про p-value:** p < 0.05 не означає «варіант B кращий». Означає «різниця
навряд чи випадкова». Дивись на довірчий інтервал — якщо він [+0.1%; +4%],
то реальний ефект може бути і мізерним, і великим. Плануй за нижньою межею.

## Важелі, коли модель не сходиться

За силою впливу (від найсильнішого):

1. **Ціна** — прямо в LTV, лінійно. +30% до ціни часто коштує менше конверсії ніж здається
2. **Утримання** — прямо в LTV. Один зайвий місяць життя = +12% LTV при retention 8
3. **CR лендінга** — прямо в CAC. З 2% до 3% = CAC падає на третину
4. **Канал** — інший канал = інший CPC. Іноді на порядок
5. **Маржа/COGS** — часто найшвидший фікс для AI-продуктів (ліміти, дешевша модель, кеш)

Порядок дій: спершу перевір чи не завищений LTV (найчастіше причина), потім
шукай дешевший канал, і тільки потім оптимізуй лендінг.
