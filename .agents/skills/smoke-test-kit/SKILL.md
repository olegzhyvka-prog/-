# Smoke Test Kit — тест у ринку за один день

## Передумова
Цей скіл не вирішує **що** тестувати. Це вирішує `hypothesis-dossier`.
Якщо досьє немає — зупинись і зроби його. Інакше зберемо гарний лендінг,
який нічого не доводить.

З досьє тобі потрібні: офер, ціна, головна метрика, kill-критерії, потрібна вибірка.

---

## Збірка за 6 кроків (реалістично — 4-6 годин)

### 1. Лендінг (1.5-2 год)
- Дизайн-мова: `design-system` → токени продукту
- Верстка: `site-builder`
- Текст: `copywriting` (офер) + `page-cro` (структура)

**Мінімальний склад для тесту** — не більше:
```
Герой: обіцянка + підобіцянка + CTA + один візуальний якір
Проблема: 3 пункти, які впізнаються
Як це працює: 3 кроки
Ціна: ВИДИМА. Без ціни тест не доводить головного
Доказ: те що є чесного (кількість, відгук, логотип, скрін)
CTA-повтор
FAQ: 4-6 питань = зняття заперечень
```
Не роби: блог, «про нас», карусель відгуків, чат-віджет. Це шум для тесту.

**Важливо:** ціна має бути на сторінці. Лендінг без ціни вимірює цікавість,
а не готовність платити — тобто найважливіше припущення лишається неперевіреним.

### 2. Події (30 хв)
Розміть **до** заливу трафіку. Після — пізно, дані вже втрачені.

```js
// Мінімальний набір. Більше не треба, менше — не прочитаєш воронку.
track('page_view',      { variant, utm_source, utm_campaign })
track('scroll_50')                       // чи взагалі читають
track('pricing_view')                    // дійшли до ціни
track('cta_click',      { position })    // hero / mid / footer — де саме
track('form_start')
track('lead_submit',    { plan })
track('checkout_start', { plan, price })
track('purchase',       { plan, value }) // головна метрика при preorder-тесті
```

Інструмент: **PostHog** — безкоштовного тарифу вистачає для тесту, є воронки,
теплокарти, записи сесій і фіче-флаги для A/B в одному місці.
Альтернатива GA4 — важче і повільніше показує воронку.
Деталі розмітки — скіл `analytics-tracking`.

**Записи сесій увімкни обов'язково.** 20 переглядів записів дають більше розуміння
чому не конвертить, ніж будь-яка таблиця.

### 3. Приймання наміру (1 год)

| Тип тесту | Реалізація | Час |
|---|---|---|
| Передоплата | **Stripe Payment Link** — окремий продукт, знижка «ранній доступ», 100% повернення | 20 хв |
| Fake door | Кнопка «Купити» → екран «запускаємось за 2 тижні, лишіть email» | 15 хв |
| Заявка | Форма → Google Sheets через Apps Script або Tally | 20 хв |

**Етика fake door:** екран після кліку має чесно казати що продукту ще немає.
Обіцяв знижку — виконай. Гроші за неіснуюче не бери (передоплата з реальним
дедлайном і поверненням — це нормально, обман — ні).

### 4. UTM (10 хв)
Без дисципліни в UTM результати не читаються.
```
?utm_source=meta&utm_medium=cpc&utm_campaign=<гіпотеза>&utm_content=<креатив>&utm_term=<аудиторія>
```
`utm_content` = точна назва файлу креативу (див. `video-assembly`).
Одна назва в кабінеті = одна в UTM = одна у файлі. Інакше через тиждень хаос.

### 5. Хостинг (15 хв)
Статичний HTML → Vercel / Netlify / Cloudflare Pages. Безкоштовно, домен за 5 хвилин.
Для тесту піддомен цілком годиться — окремий домен купуй після GO.

⚠️ Перед заливом реклами: **політика конфіденційності + контакти + робочі посилання.**
Google і Meta відхиляють лендінги без них — і ти втратиш день на модерації.

### 6. Передпольотний чекліст (15 хв)
- [ ] Ціна видима
- [ ] Усі події спрацьовують — перевір у реальному часі, натисни сам
- [ ] Мобільна версія (80%+ трафіку — телефон)
- [ ] Швидкість: LCP < 2.5 с (інакше половина піде до першого екрана)
- [ ] Форма реально надсилає і ти отримуєш сповіщення
- [ ] Stripe у **живому** режимі, не тестовому
- [ ] Політика конфіденційності + контакти
- [ ] UTM працюють — перейди за посиланням і перевір що дані дійшли
- [ ] Kill-критерії з досьє записані і видимі
- [ ] Ліміт бюджету виставлено в кабінеті (страховка від помилки)

## Крок 0 — чи взагалі розв'язне питання за наявний бюджет

**Роби це ПЕРШИМ, до лендінга.** Найдорожча помилка цього скіла — зібрати
бездоганний тест метрики, яку наявний бюджет не може виміряти в принципі.

```bash
python3 ../unit-economics-calc/scripts/sample_size.py size --baseline <CR> --lift 0.30
```
Помнож потрібну вибірку на CPC. Якщо вийшло **більше за мандат** —
зупинись і зміни питання, а не додавай днів. Днями це не лікується.

| Питання | Потрібно при CR 0.5% | Потрібно при CR 3% |
|---|---|---|
| A/B різниця в оплатах | 8 000+ візитів на плече | ~1 200 на плече |
| «CAC вище чи нижче стелі» (одне плече) | ~400-600 візитів | ~400 візитів |

**Правило:** A/B — це розкіш для метрик з CR > 5%. За $300 розв'язне
одноплече питання «проходимо стелю CAC чи ні», а не порівняння двох лендінгів.
Дешевий тест дорогої метрики — це не дешевий тест, а гроші без відповіді.

## Скільки лити і як довго

З `unit-economics-calc` візьми потрібну вибірку. Орієнтир для рішення
«працює / не працює» при очікуваному CR 2-3%: **400-600 візитів**.

**Вікно тесту має містити робочі дні пн-чт.** Пт-Сб-Нд для B2B-чека —
це не вибірка. Перевір календар до запуску, а не при розборі.

- **Мінімум 3 дні поспіль.** Дні тижня різні; вівторок ≠ неділя.
- Не чіпай кампанію перші 48 годин. Алгоритм навчається, ранні цифри брешуть.
- Не роби висновків до досягнення розрахункової вибірки. Взагалі.

## Що робити ще до лендінга у чутливих нішах
Якщо ніша сіра (фінанси, здоров'я, заробіток, знайомства) — **спершу тест модерації**:
$20 на просту кампанію, перевірити чи взагалі пропускають. Це найдешевший тест
у всьому процесі і рятує від тижня марної роботи.
