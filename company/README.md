# Цифрова компанія — 21 працівник

Постійний штат для solo-засновника. Не набір промптів, а команда з памʼяттю, яка
накопичує знання про **цей конкретний бізнес** і перенавчається щомісяця.

## Чим працівник відрізняється від субагента

| | Звичайний субагент | Працівник тут |
|---|---|---|
| Памʼять | немає — щоразу з нуля | тека на диску, вшивається в промпт при старті |
| Помилки | повторює вічно | `lessons.md`: помилка → правило назавжди |
| Процедури | вигадує заново | `playbook.md`: те, що вже спрацювало |
| Рішення | переглядає по колу | `decisions.md`: чому так зроблено, з датою |
| Кілька бізнесів | плутає їх | ремесло спільне, факти ізольовані по проєктах |
| Розвиток | застигає | місячний протокол перенавчання з інтернету |
| Межі | розмиті | зона відповідальності, червоні лінії, право вето |
| Правда | схильний вигадувати | заборона на вигадані факти — головне правило |
| Виживання | зникає з сесією | лежить у git, переживає перезапуск і зміну машини |

Механізм той самий (`.claude/agents/`), різниця в дисциплінi: **памʼять, межі й навчання**.

## Як користуватись

Просто говоріть зі мною звичайною мовою. Я оркестратор: розберу задачу, виберу працівника,
складу тех-завдання, прийму результат і перекладу вам по суті.

```
«Треба лендінг для нового продукту»
  → market-researcher (мова клієнта) → conversion-copywriter (текст)
  → brand-designer (макет) → fullstack-engineer (верстка) → data-analyst (трекінг)

«Чому люди не платять?»
  → data-analyst (де тече воронка) → customer-success (причини) → product-strategist

«Скільки це коштуватиме?»
  → finance-controller
```

Хочете конкретного — назвіть: «хай `security-engineer` перевірить авторизацію».

### Команди

| Команда | Що робить |
|---|---|
| `/team` | показати штат, вибрати виконавця під задачу |
| `/team-training` | запустити місячне перенавчання (або одного працівника) |
| `/team-retro` | розбір завершеної роботи → уроки в памʼять працівників |
| `/audit` | аудит бізнесу або частини: сайт, дизайн, бізнес-модель, безпека, гроші |

## Кілька бізнесів — без змішування

Одна команда обслуговує кілька ваших проєктів. Памʼять розділена так, щоб знання
накопичувались, а факти не текли:

| | Приклад | Переноситься? |
|---|---|---|
| **Ремесло** | «міграцію NOT NULL робити у два кроки», «Google змінив правила цитування» | **так** — капітал по всіх проєктах |
| **Факти бізнесу** | MRR, клієнти, ціни, кольори бренду, юрисдикція | **ні — ніколи** |

Тест: «Це буде правдою в іншому бізнесі?» Так → ремесло. Ні → факти проєкту.
У кожному завданні проєкт називається явно; не названий — працівник питає, а не вгадує.

## Перший крок

**Заповніть `company/projects/<проєкт>/founder-context.md`.** Це єдине, що зараз обмежує
команду: вони професійні, але поки нічого не знають про ваш бізнес. Скажіть «заповнимо
контекст» — я проведу по пунктах.

Далі: «що робити першим?» → `chief-of-staff` розкладе на тиждень.

## Правила, які тримають систему

1. **Правда понад усе.** Не перевірив — не заявляй. Не знаєш — скажи «не знаю». Вигадані
   числа й цитати — найтяжче порушення.
2. **Памʼять оновлюється завжди.** Робота без оновлення памʼяті не вважається завершеною.
3. **Кожен у своїй зоні.** Чуже передається профільному, а не робиться наполовину.
4. **Оборотне робимо, незворотне питаємо.** Гроші, публікації, видалення даних — тільки
   з вашим підтвердженням.
5. **Вето працює.** Безпека, якість і право можуть зупинити запуск. Скасувати можете лише ви.
6. **Раз на місяць команда вчиться** і викидає застаріле.
