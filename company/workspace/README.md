# Робочі теки задач

Тимчасовий простір для роботи над конкретною задачею. Протокол —
`company/protocols/workspace.md`.

```
company/workspace/
  YYYY-MM-DD-<назва>/     активна задача
    task.md               бриф + чекліст (переписується в ході роботи)
    findings.md           спільний блокнот ланцюга працівників
    dead-ends.md          що НЕ спрацювало — не видаляється
    report.md             фінал для засновника
  _done/                  завершені задачі
```

**Це не памʼять.** Тека тимчасова: цінне з неї переїжджає в памʼять працівників
(ремесло → `lessons.md`/`playbook.md`, факти бізнесу → `projects/<проєкт>/state.md`),
а сама тека йде в `_done/`.

**Заводиться не завжди.** Тільки якщо в ланцюгу двоє й більше працівників, робота
довша за кілька кроків, або результат дорогий. На дрібницю — зайва бюрократія.

## Навіщо це

**Чекліст у `task.md`** — механізм утримання уваги. На довгій роботі початкове завдання
«тоне» в середині контексту, і працівник поступово дрейфує в суміжне. Переписування
чекліста повертає ціль у кінець контексту. Прийом з архітектури Manus.

**`findings.md`** — прибирає мене як посередника між працівниками. Те, що знайшов
перший, доходить до четвертого дослівно, а не переказом.

**`dead-ends.md`** — невдалі спроби залишаються видимими навмисне. Прибрана помилка
це помилка, яку повторить наступний.
