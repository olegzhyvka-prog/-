## Скрипт 1 — motion-графіка з HTML

```bash
python3 scripts/render_motion.py scene.html hook.mp4 \
    --duration 5 --fps 30 --size 1080x1920
```

**Як це працює:** Playwright відкриває HTML, ставить час CSS-анімацій вручну
кадр за кадром і знімає скріншоти → ffmpeg збирає в MP4. Рендер детермінований:
той самий HTML завжди дає той самий результат, кадр не «пливе».

| Прапорець | Дефолт | Нотатка |
|---|---|---|
| `--duration` | 5 | секунд |
| `--fps` | 30 | 30 достатньо для соцмереж, 60 — тільки для швидкого руху |
| `--size` | 1080x1920 | 9x16. Для стрічки `1080x1350`, для YouTube `1920x1080` |
| `--lossless` | off | PNG замість JPEG: якісніше, але втричі повільніше |

**Швидкість:** ~0.7 с на кадр у 1080x1920. П'ятисекундний ролик ≈ 2 хвилини.
Для 15-секундного розраховуй на 5-6 хвилин. Плануй це в таймлайні.

### Як писати сцену
- Розмір `body` = точний розмір відео. Ніякого responsive.
- Тільки CSS `@keyframes` — скрипт керує їх часом. `setTimeout` і `requestAnimationFrame`
  ігноруються (окрім хука `window.onFrame(t)`, якщо треба щось малювати вручну).
- Останній кадр має бути статичним і читабельним — це прев'ю в стрічці.
- Візуальну мову бери з `design-system/references/effects.md` (aurora, шум, свічення).
- Текст крупно: у стрічці ролик дивляться з екрана 6 см. Заголовок ≥ 100px при 1080 ширини.

## Скрипт 2 — монтаж

```bash
python3 scripts/assemble.py \
  --clips hook.mp4 body.mp4 cta.mp4 \
  --out ad_v1.mp4 --format 9x16 \
  --music bg.mp3 --subs subs.srt
```

Що робить під капотом:
- приводить усі кліпи до одного розміру/fps/аудіоформату (інакше concat ламається)
- кроп по центру без чорних смуг (`--pad` — вписати з розмитим фоном, якщо в кадрі важливий текст)
- вшиває субтитри в картинку — **обов'язково**, більшість дивиться без звуку
- музика приглушується під голос через `sidechaincompress`, потім `loudnorm -14 LUFS`
  (стандарт гучності соцмереж — інакше платформа сама придушить трек)

## Скрипт 3 — пакет варіантів для тесту

```bash
bash scripts/batch_variants.sh hooks/ body.mp4 cta.mp4 out/
```
Бере всі хуки з теки, приклеює до однакового тіла і кінцівки → N готових роликів.
Це і є справжня механіка тесту креативів: **одне тіло, різні перші 3 секунди.**

## Структура рекламного ролика (працює у 2026)

```
0.0-0.8с   Крючок: рух + текст одночасно. Без логотипа, без «привіт друзі»
0.8-3.0с   Проблема впізнається. Глядач має подумати «це про мене»
3.0-8.0с   Рішення в дії: показ, а не розповідь
8.0-12с    Доказ: цифра, відгук, до/після
12-15с     Один CTA. Одна дія. Текст на екрані + голос
```

**Правила які найбільше впливають на результат:**
1. Перший кадр вирішує все. 3 секунди — і глядач пішов.
2. Ніколи не починай з логотипа. Логотип — у кінці.
3. Субтитри завжди. Це не опція.
4. Різ кожні 1.5-3 секунди. Статичний кадр довше 4 с = скрол.
5. Вертикаль за замовчуванням. Горизонт — тільки YouTube.
6. Одна ідея на ролик. Три меседжі = нуль запам'ятаного.

## Тестування креативів — механіка

Не роби «5 різних відео». Роби **сітку**: змінюй одну змінну за раз.

```
Кут (angle)   × Хук (перші 3 с) × Формат
економія часу   питання             motion-графіка
економія грошей статистика          UGC-зйомка
страх відстати  демо результату     скрінкаст
```

Стартовий пакет для тесту: **1 кут × 4 хуки** — так ти дізнаєшся що працює хук,
а не випадкове поєднання. Потім переможний хук × 3 кути.

**Іменування файлів — не дрібниця, без нього результати не читаються:**
```
<продукт>_<кут>_<хук>_<формат>_v<N>.mp4
symplexy_time_question_9x16_v2.mp4
```
Та сама назва йде в назву оголошення в рекламному кабінеті. Інакше через два
тижні ти не зрозумієш який креатив виграв.
