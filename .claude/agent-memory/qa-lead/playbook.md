# Плейбук ремесла — Пабло Ортіс (Head of Quality)

**Тип: РЕМЕСЛО — спільне для всіх проєктів.**

Мої відпрацьовані процедури і прийоми. Теорія моєї професії лежить у
`.claude/agents/qa-lead.md` — сюди йде лише те, що **я перевірив на практиці**.

Специфіка конкретного бізнесу (його команди, його конвенції, його доступи) →
`projects/<проєкт>/state.md`.

Формат:
```
## <Назва процедури>
**Коли застосовую:** ...
**Кроки:** 1... 2... 3...
**Де підтвердилось:** <проєкт> — <результат з цифрами і датою>
**Коли НЕ застосовувати:** ...
```

Плейбук **чиститься**: процедура, що більше не працює, видаляється в циклі перенавчання.
Плейбук, який тільки росте, стає непридатним.

## Приймальне тестування цифрової компанії (мета-тестування самої системи, не продукту)
**Коли застосовую:** засновник просить перевірити, чи система працівників/памʼяті/хуків
насправді працює, перш ніж на неї покластись, а не перевіряю продукт.
**Кроки:**
1. Звірити «заявлене» (CLAUDE.md, ROSTER.md, memory-protocol.md, DoD) із «фактичним»
   (реальні файли на диску) — числа, шляхи, право вето, ліміти — окремо для КОЖНОГО
   джерела правди, не довіряти жодному одному документу.
2. Перевірити, що інжектований мені на старті сесії контекст (система/памʼять) збігається
   з `git diff HEAD` реального файлу — стале ін'єктування контексту саме по собі клас
   дефекту, який легко пропустити, бо «виглядить як правда».
3. Хуки — прогнати наживо там, де це безпечно (SessionStart, SubagentStop через
   симуляцію stdin), і статично + ізольованими regex/boundary-тестами там, де живий
   запуск незворотний (Stop-хук з автокомітом+пушем).
4. Перевірити не лише «чи існує файл X, на який посилаються», а й «чи логіка, що його
   використовує, коректна на межах» (кількість = 200, 12-14, 111, регістр символів).
5. Прочитати `dead-ends.md` робочої теки ПЕРЕД тим, як писати власний — інший працівник
   у тому ж ланцюгу міг уже наштовхнутись на той самий системний дефект незалежно;
   підтвердження другим незалежним відтворенням сильніше за одне спостереження.
**Де підтвердилось:** symplexy, 2026-08-01 — знайдено 6 дефектів (Д1 висока
серйозність: case-sensitive сканер секретів; Д6 висока: harness блокує Write
report-подібних файлів у workspace, підтверджено двічі незалежно з data-analyst).
**Коли НЕ застосовувати:** коли тестую фічу продукту засновника, а не саму систему
працівників — там працює звичайний тест-план з приймальними критеріями, не це мета-ревʼю.
