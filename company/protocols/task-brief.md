# Форма тех-завдання

Працівник **не бачить розмови з засновником**. Він бачить лише те, що написано в завданні,
плюс свою памʼять і файли, які прочитає. Тому неповне завдання = неповна робота, і винен
оркестратор, а не працівник.

## Форма

```
## Проєкт
<назва з company/PROJECTS.md — обовʼязково, працівник не вгадує>

## Задача
<одне речення: який результат потрібен>

## Навіщо
<яке рішення засновника це змінить / яку проблему вирішує>

## Контекст
- Продукт / стадія: <або посилання на company/projects/<проєкт>/founder-context.md>
- Що вже відомо: <факти>
- Що вже пробували: <щоб не повторював>
- Файли, які треба прочитати: <шляхи>

## Готово, коли
- [ ] <перевірюваний критерій>
- [ ] <перевірюваний критерій>

## Обмеження
- Бюджет: <гроші / час>
- Технічні: <стек, сумісність>
- Не робити: <явні межі скоупу>

## Артефакт
Файл: <очікуваний шлях і формат>

## Робоча тека
company/workspace/<YYYY-MM-DD-назва>/   ← або «не потрібна» для дрібної задачі
Файли вже створені оркестратором — редагуй їх (Edit), не створюй нові.
Переписуй чекліст у task.md по ходу. Знахідки → findings.md. Невдалі спроби → dead-ends.md.
Результат повертай ТЕКСТОМ у звіті — файл-звіт створить оркестратор.

## Передати далі
<кому і що після завершення, або «нікому»>

## Обов'язково
1. Прочитай своє ремесло (.claude/agent-memory/<твій-slug>/) і факти проєкту
   (.claude/agent-memory/<твій-slug>/projects/<проєкт>/) перед роботою.
2. Не бери фактів, чисел, цитат чи токенів бренду з інших проєктів.
3. Дотримуйся company/protocols/definition-of-done.md.
4. Онови памʼять у кінці — ремесло і факти проєкту в різні файли.
5. Не вигадуй факти й числа. Немає даних — скажи це.
```

## Правила складання

**Пиши результат, не процес.** «Дай план з трьох каналів з розрахунком CAC» краще, ніж
«подумай про маркетинг».

**Критерій «готово» мусить бути перевірюваним.** Не «зроби добре», а «сторінка відкривається,
форма відправляє лід у базу, є стан помилки».

**Дай те, що вже пробували.** Інакше працівник витратить час на мертвий шлях. Це є в його
`lessons.md`, але контекст компанії ширший за його зону.

**Назви межі.** «Не чіпай схему БД», «не витрачай бюджет», «лише чернетка».

**Одна задача — один працівник.** Потрібні двоє → два завдання і явна послідовність.

## Даємо мінімально необхідне, а не все, що є

Спокуса — вкласти в завдання весь відомий контекст: хай знає більше, гірше не буде.
Буде гірше. Зайвий контекст коштує токенів на кожному запуску, розмиває увагу і —
головне — розносить те, що мало лишитись в одному місці.

**Не передається в завдання за замовчуванням:**

| Що | Чому |
|---|---|
| факти інших проєктів засновника | найдорожча помилка системи — число одного бізнесу в іншому |
| памʼять інших працівників | чужі уроки без чужого контексту застосовуються неправильно |
| повний профіль засновника | давати те, що стосується цієї задачі, а не все |
| сирі транскрипти, довгі звіти цілком | давати шлях до файлу, працівник прочитає, якщо треба |
| гіпотези і напрями, які не стосуються задачі | читаються як контекст, до якого треба щось додати |

**Передається:** проєкт, факти по задачі, файли для читання, межі. Тобто те, без чого
роботу не зробити — і нічого понад це.

Правило одне: **великі артефакти не переказуються, а лишаються у файлі.** У завданні —
шлях, а не вміст.

## Мінімальна версія

Для дрібної задачі достатньо:

```
## Проєкт
<назва>
## Задача
<результат>
## Контекст
<файли + 2-3 факти>
## Готово, коли
<критерій>
## Обов'язково
Прочитай памʼять (ремесло + проєкт), дотримуйся DoD, онови памʼять, не вигадуй числа,
не змішуй проєкти.
```

## Антипатерни

| Погано | Чому |
|---|---|
| «Займись SEO» | немає результату, критерію і межі — робота буде розмита |
| «Зроби як краще» | працівник вирішить за тебе те, що вирішує засновник |
| завдання без контексту продукту | працівник почне вигадувати або витратить запуск на питання |
| завдання двом на одну тему | дублювання і суперечливі результати |
| «швидко подивись» без критерію | не буде зрозуміло, приймати роботу чи ні |
| **не названий проєкт** | працівник візьме факти не того бізнесу — найдорожча помилка |
