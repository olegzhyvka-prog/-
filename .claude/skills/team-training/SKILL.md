# Місячне перенавчання команди

Повний протокол — `company/protocols/monthly-training.md`. Прочитай його перед запуском.

## Аргументи

| Виклик | Що робити |
|---|---|
| `/team-training` | повний цикл за ротацією хвиль |
| `/team-training ai-engineer` | перенавчити конкретного працівника |
| `/team-training all` | усіх 20 (дорого — лише за прямим проханням) |

## Крок 1 — визнач склад

Прочитай `company/ledger/training-log.md` — хто перенавчався останніми і чия черга.

Ротація (деталі в протоколі):

- **Хвиля A, щомісяця** — `ai-engineer`, `seo-aeo-lead`, `paid-ads-buyer`,
  `legal-compliance`, `sales-closer` (найшвидше змінювані зони).
- **Хвиля B, раз на 2 місяці** — `growth-lead`, `content-strategist`,
  `conversion-copywriter`, `data-analyst`, `customer-success`, `security-engineer`.
- **Хвиля C, раз на 3 місяці** — решта девʼятеро.

Позачергово додай будь-кого, у чиїй зоні сталась велика зміна.

## Крок 2 — запусти працівників

По 3–5 паралельно, не більше. Кожному — таке завдання:

```
## Задача
Місячний цикл перенавчання у твоїй зоні за company/protocols/monthly-training.md.

## Що зробити
1. Прочитай свій skills-watch.md — там твої джерела і минулі цикли.
2. Перевір джерела через WebSearch/WebFetch за чотирма питаннями:
   - Що ЗЛАМАЛОСЬ у моїй зоні за останній місяць? (платформи, алгоритми, API, ціни, закони)
   - Що ЗДЕШЕВШАЛО або спростилось? (інструменти, що прибирають ручну роботу)
   - Що ВИЗНАНО ХИБНИМ? (практики, які галузь відкинула — і чи є вони в моєму плейбуці)
   - Що НОВОГО в ремеслі? (методики, варті додавання)
3. Перевір також: GitHub (topics claude-code, agent-skills, awesome-*),
   релевантні сабреддіти, Hacker News, arXiv у своїй зоні, офіційні changelog'и.
4. Кожна знахідка — з посиланням і датою. Без джерела не існує.

## Критерій прийняття знахідки
- джерело перевірене, не рекламний пост і не чутка;
- стосується НАШОГО бізнесу і стадії;
- змінює те, як ти працюєш, а не просто цікаво;
- вигода > вартості переходу.

## Готово, коли
- [ ] skills-watch.md оновлений повним журналом циклу
- [ ] playbook.md: прийняті зміни вписані як конкретні процедури, не посилання
- [ ] playbook.md: ЗАСТАРІЛЕ ВИДАЛЕНО (це половина сенсу протоколу)
- [ ] MEMORY.md оновлений, якщо змінилось те, що ти мусиш знати завжди (ціни, ліміти, правила)
- [ ] названо, що вимагає рішення засновника (або «немає»)

## Червоні лінії
- Не додавай навичку без джерела.
- Не змінюй свою роль, межі відповідальності і свої червоні лінії.
- Не встановлюй нічого і не витрачай гроші.
- Плейбук не має тільки рости: додав — подумай, що видалити.
```

## Крок 3 — зведення

Запусти `chief-of-staff` із завданням зібрати звіти і записати цикл у
`company/ledger/training-log.md` за формою в тому файлі. Нагорі — окремий блок
**«Вимагає рішення засновника»**.

## Крок 4 — перевірка здоровʼя памʼяті

Заодно `chief-of-staff` перевіряє (за `company/protocols/memory-protocol.md`):

```bash
for f in .claude/agent-memory/*/MEMORY.md; do
  n=$(wc -l < "$f")
  [ "$n" -ge 200 ] && echo "ПЕРЕВИЩЕНО 200: $f ($n)"
done
```

Плюс: чи мають числа дати, чи немає секретів, чи немає здогадів, що виглядають як факти.

## Крок 5 — доповідь засновнику

**Коротко: 3–7 пунктів.** Не переказ усіх звітів.

```
## Перенавчання за <місяць>
Перенавчено: <кількість> працівників (<slug'и>)

### Вимагає вашого рішення
- <зміна> → <що це для нас означає> → <що пропонуємо>

### Що змінилось у роботі команди
- <slug>: <зміна>

### Що застаріло і прибрано
- <slug>: <що>
```

Немає нічого, що вимагає рішення — так і скажи. Не вигадуй важливість, щоб цикл
виглядав продуктивним. Місяць без змін у повільній зоні — нормальний результат.
