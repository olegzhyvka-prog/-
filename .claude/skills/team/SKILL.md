# Штат: орієнтація і вибір виконавця

## Крок 1 — прочитай реєстр

Прочитай `company/ROSTER.md`. Не покладайся на памʼять про склад команди — реєстр
може змінитись.

## Крок 2 — визнач тип запиту

**«Хто в мене є?»** → покажи стислу таблицю за групами (керівне ядро, інженерія, дані,
зростання, дохід). Не вивалюй усіх з описами — це нечитабельно. Групи + імена + одна
фраза «коли кликати».

**«Хто зробить X?»** → назви одного виконавця і, якщо потрібна послідовність, ланцюг.
Обґрунтуй одним реченням. Одразу запропонуй запустити.

**«Розподіли роботу»** (велика розмита задача) → не розкладай сам. Запусти
`chief-of-staff` — це її робота. Виняток: задача явно в одній зоні.

## Крок 3 — вибір виконавця

Дивись у `company/ROSTER.md` колонку «Викликати коли». Ланцюги для типових задач —
у `company/protocols/orchestration.md`.

Правила вибору:

- **Сумнівна зона** → назви двох і спитай, або запусти обох послідовно (не паралельно
  на один артефакт).
- **Задача про гроші** → `finance-controller` завжди в ланцюгу.
- **Задача про числа** → `data-analyst` перший, до будь-яких висновків.
- **Задача про клієнта** → `market-researcher` перший, інакше решта працюватиме на здогадах.
- **Публічний запуск** → `security-engineer` і `legal-compliance` обовʼязково перед запуском.
- **Більше 5 паралельно** → не роби. Розбий на хвилі.

## Крок 3.5 — план до запуску

Ланцюг із трьох і більше працівників, довга робота або дорогий результат → **покажи план
засновнику до запуску** за формою в `company/protocols/orchestration.md`: хто, в якому
порядку, що дає, чого не робимо, що припущено. Одне його речення тут дешевше за чотири
переписаних артефакти потім.

Один-два працівники — план не потрібен, запускай.

## Крок 4 — запуск

Склади тех-завдання за `company/protocols/task-brief.md` і запусти через `Agent`
з `subagent_type: <slug>`.

Обовʼязково в кожному завданні:
- **назва проєкту** (рядок `## Проєкт`) — див. `company/PROJECTS.md`. Працівник не вгадує,
  над яким бізнесом працює, інакше візьме чужі числа;
- контекст (працівник не бачить розмови із засновником);
- шляхи до файлів, які треба прочитати;
- перевірюваний критерій «готово»;
- нагадування: прочитати памʼять (ремесло + проєкт), дотримуватись DoD, оновити памʼять,
  не вигадувати числа, не змішувати проєкти.

Скіл під підзадачу працівник обирає **сам** — у розділі 5 його `MEMORY.md` є таблиця
«підзадача → скіл». Не нав'язуй скіл у завданні, крім випадку, коли знаєш щось, чого
немає в його таблиці.

## Створення нового проєкту

Засновник називає новий бізнес → створи теки і скажи, що контекст треба заповнити:

```bash
P=<назва>
mkdir -p company/projects/$P/ledger
for d in .claude/agent-memory/*/; do mkdir -p "$d/projects/$P"; done
```

Скопіюй шаблони `state.md`, `decisions.md`, `lessons.md` з наявного проєкту (замінивши
назву), додай рядок у `company/PROJECTS.md` і створи `founder-context.md` за зразком.
Ремесло працівників при цьому **не копіюється і не скидається** — воно вже працює на
новий проєкт з першого дня. У цьому весь сенс поділу.

## Крок 5 — приймання

Перевір результат за `company/protocols/definition-of-done.md`. Не сходиться —
поверни на доопрацювання з конкретним переліком, не переказуй засновнику неготове.

## Стан памʼяті команди

Якщо засновник питає «що команда вже знає» або «чи вони вчаться» — покажи стан:

```bash
for d in .claude/agent-memory/*/; do
  n=$(basename "$d")
  l=$(grep -c '^## 20' "$d/lessons.md" 2>/dev/null || echo 0)
  p=$(grep -c '^## ' "$d/playbook.md" 2>/dev/null || echo 0)
  echo "$n: уроків $l, процедур $p"
done
```

Порожня памʼять у всіх — нормально до першої реальної роботи. Порожня памʼять
у працівника, який уже виконував задачі, — поломка протоколу, фіксуй у
`company/ledger/lessons.md`.

Це показує **ремесло** — те, що працює на всі проєкти. Стан конкретного бізнесу
дивись у `.claude/agent-memory/*/projects/<проєкт>/state.md`.

## Чого не робити

- Не виконуй профільну роботу сам, коли для неї є працівник (крім задач до 2 хвилин).
- Не запускай працівника без тех-завдання.
- Не запускай двох на один і той самий артефакт одночасно.
- Не вигадуй результат працівника, який ще не завершив.
