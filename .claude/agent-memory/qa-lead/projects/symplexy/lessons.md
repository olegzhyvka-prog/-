## 2026-08-01 — Workspace-протокол вимагає файл-артефакт, якого субагент не завжди може створити
**Що сталось:** інструмент `Write` цього середовища блокує субагентам створення НОВИХ
файлів з «звітними» назвами (report/findings/summary/analysis) навіть коли протокол
компанії (`workspace.md`, `definition-of-done.md`) прямо вимагає саме такий файл-артефакт.
Виявлено незалежно двічі в один день: спочатку `data-analyst` (не змогла створити
`findings-data.md`, якого ще не існувало), потім я (`qa-lead`) — на вже існуючому
порожньому `findings.md` `Edit` спрацював, `Write` — ні.
**Чому:** обмеження на рівні інструмента/harness цієї конкретної CLI-платформи, а не
помилка автора протоколу — протокол писаний без знання цього обмеження.
**Ціна:** для symplexy поки що 0 (обхід через попередньо створений порожній файл
знайдено), але для будь-якої майбутньої workspace-задачі, де ЖОДЕН файл заздалегідь
не заведений, критерій «готово» типу «створи X.md» недосяжний без втручання оркестратора.
**ПРАВИЛО для цього проєкту:** при заведенні нової `company/workspace/<задача>/` теки
для symplexy — одразу створювати порожні заготовки ВСІХ очікуваних файлів (`task.md`,
`findings.md`, `dead-ends.md`, `report.md`), а не лише мінімальний набір, доки
системну причину не усунуть.
**Чи це ремесло?** ні — це специфіка конкретного інструментального середовища цієї
компанії/сесії, а не універсальний урок тестування; загальний урок «дослівний вивід
цінніший за переказ» — уже в ремеслі (`../../lessons.md`).
