# Symplexy — уроки: Даріо Феррі (Head of Product / CPO)

**Тип: ФАКТИ ПРОЄКТУ — не переносити в інші бізнеси.**

Уроки, правдиві **тільки для цього бізнесу**: його клієнти, його стек, його ринок,
його аудиторія.

Урок, який працюватиме і в іншому бізнесі → на рівень вище, у `../../lessons.md`.

Формат:
```
## YYYY-MM-DD — <заголовок>
**Що сталось:** факти.
**Чому:** причина.
**Ціна:** час / гроші.
**ПРАВИЛО для цього проєкту:** наказова форма.
**Чи це ремесло?** ні — інакше урок мав би бути рівнем вище.
```

## 2026-08-03 — «1 500 відвідувачів» у цьому проєкті всі читали як поріг доходу

**Що сталось:** число 1 500 відв./міс закріпилось у контексті бізнесу як цільове число і
фактично працювало як мета монетизації — на нього спиралися план трафіку, реклама і
черговість трьох робіт. Насправді це поріг, після якого партнерська програма **розгляне
заявку**. До першої гривні від нього ще кілька множників.

**Чому:** число прозвучало в розмові без одиниці виміру «чого саме поріг», і всі
підхопили його як фінішну лінію.

**Ціна:** уся послідовність «доробити сайт → реклама → трафік → партнерки» побудована
навколо числа, яке не є метою. Реклама вже запускається під цю логіку.

**ПРАВИЛО для цього проєкту:** поруч із «1 500» завжди писати «— це поріг подання заявки,
не поріг доходу»; метрикою монетизації Symplexy вважати **дохід на відвідувача (RPV)**,
поки він не виміряний — писати «не виміряно».

**Чи це ремесло?** ні — конкретне число і конкретна модель цього бізнесу.

## 2026-08-03 — Продукт побудовано для аудиторії A, а гроші має дати аудиторія B, для якої не зроблено нічого

**Що сталось:** Symplexy повністю спроєктований під українського SMB-підприємця (безкоштовно
для нього). Платити мають ШІ-сервіси. За весь час не відбулось жодного контакту з жодним
ШІ-сервісом: 0 підключених програм, 0 виплат, немає ні медіа-кіту, ні даних про аудиторію,
ні кейсу, ні навіть зареєстрованої юрособи, на яку можна прийняти гроші.

**Чому:** двосторонній ринок будували з одного боку. Сторона попиту (користувач) отримала
сайт, каталог і асистента; сторона пропозиції грошей — нічого.

**Ціна:** дохід 0 при готовому продукті з 200 інструментами.

**ПРАВИЛО для цього проєкту:** будь-який наступний крок Symplexy оцінювати питанням
«що це дає **платнику**?». Крок, який покращує тільки досвід безкоштовного користувача
(нові інструменти, кращий асистент, гарніший лендинг), не наближає дохід сам по собі —
і має йти в парі з кроком у бік платника.

**Чи це ремесло?** узагальнення — так, воно піднято в `../../lessons.md`. Тут лишається
конкретика цього бізнесу.
