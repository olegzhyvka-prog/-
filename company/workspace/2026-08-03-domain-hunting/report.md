## Частина 1. Як це роблять зараз (2026) — перевірені інструменти

### 1.1. Ключова зміна інфраструктури: WHOIS помер, RDAP переміг

Це найважливіший факт для будь-якої автоматизації доменів, і він свіжий:

> **28 січня 2025** RDAP став офіційним джерелом реєстраційних даних gTLD замість WHOIS. Реєстри й реєстратори більше не зобовʼязані підтримувати WHOIS — **крім .com, .name і .post**. До вересня 2025 **374 gTLD вимкнули WHOIS повністю.**
> — [ICANN Update: Launching RDAP; Sunsetting WHOIS](https://www.icann.org/en/announcements/details/icann-update-launching-rdap-sunsetting-whois-27-01-2025-en)

**Наслідок:** будь-який скрипт чи туторіал на `python-whois` — це техборг. RDAP — це JSON по HTTPS, безкоштовний, без ключа, без парсингу тексту. `https://rdap.verisign.com/com/v1/domain/<name>.com` → **404 = вільний**, 200 = зайнятий.

### 1.2. Три рівні того, як реально працюють люди

| Рівень | Хто так робить | Інструменти |
|---|---|---|
| **Рівень 1 — «LLM + масовий чек»** | стартапери, що шукають назву разово | Namelix / ChatGPT → експорт → bulk-checker |
| **Рівень 2 — воркфлоу в no-code** | інді-хакери, агенції | n8n / Make + реєстратор API + Google Sheets + алерт |
| **Рівень 3 — зона-файли й drop-catching** | доменні інвестори | ICANN CZDS, ExpiredDomains.net, DropCatch |

**Рівень 1 — конкретика.** Типовий воркфлоу 2026: *згенерувати 1000 назв → відфільтрувати за довжиною/ключовими словами → масова перевірка → експорт вільних → шортліст 20* ([Instant Domain Search](https://instantdomainsearch.com/learn/guides/best-bulk-domain-search-tools)). **Namelix** — не обгортка над GPT, а власна модель, натренована саме на коротких брендованих неологізмах, з вбудованою перевіркою доменів ([огляд](https://www.tooljunction.io/ai-tools/namelix)). Важливо: generic-LLM видає словникові композити, спеціалізована модель — вигадані слова.

**MCP-сервери — те, що зʼявилось саме під Claude:**
- **`domain-search-mcp`** (MIT, npm, [github.com/dorukardahan/domain-search-mcp](https://github.com/dorukardahan/domain-search-mcp)) — 12 інструментів (`search_domain`, `bulk_search`, `suggest_domains_smart`, `expiring_domains`, `hunt_domains`, `check_socials`), каскад **RDAP → GoDaddy → WHOIS**, **ключі API не потрібні**. Ставиться одним рядком у `.mcp.json`:
  ```json
  {"mcpServers":{"domain-search":{"type":"stdio","command":"npx","args":["-y","domain-search-mcp@latest"]}}}
  ```
  *(заявa README проєкту — незалежно не перевірено: не встановлювався й не запускався)*
- **Instant Domain Search MCP** ([instantdomainsearch.com/mcp](https://instantdomainsearch.com/mcp)) — без автентифікації, sub-10ms API, `search_domains` для bulk по багатьох TLD.
- **GoDaddy MCP** ([developer.godaddy.com/mcp](https://developer.godaddy.com/mcp)) — офіційний, але потребує акаунт.

**Рівень 2 — конкретика.** Готові шаблони n8n:
- [«Domain availability monitor with Porkbun, Google Sheets & multi-channel alerts»](https://n8n.io/workflows/10378-domain-availability-monitor-with-porkbun-google-sheets-and-multi-channel-alerts/) — перевіряє список **кожні 30 хвилин** через Porkbun API, алерти в Gmail + Discord.
- [«Namesilo bulk domain availability checker»](https://n8n.io/workflows/3047-namesilo-bulk-domain-availability-checker/) — батчі з урахуванням rate limits, вивід в Excel.
- Apify-актори: `acme-ai/free-domains-checker-ai`, `marielise.dev/ai-domain-finder` (RDAP-verified).

**Рівень 3 — конкретика.** Те, чого не бачать «AI-генератори назв»:
- **ICANN CZDS** ([czds.icann.org](https://czds.icann.org/)) — заявка на доступ до **зон-файлів** gTLD. Безкоштовно, доступ мінімум 3 місяці, викачка раз на 24 год, зони оновлюються 00:00–06:00 UTC. Verisign за .com/.net направляє саме сюди ([verisign.com/resources/zone-file](https://www.verisign.com/resources/zone-file/)). Відкриті клієнти: [pyCZDS](https://pypi.org/project/pyCZDS/), [acidvegas/czds](https://github.com/acidvegas/czds).
  **Найпотужніший безкоштовний канал:** diff вчорашньої і сьогоднішньої зони .com дає точний список того, що звільнилось за добу. Платні сервіси роблять те саме.
- **ExpiredDomains.net** — безкоштовні щоденні списки для 676 TLD, включно з pending-delete.
- **DropCatch / SnapNames / Gname** — перехоплення на момент видалення. DropCatch тримає мережу **1000+ реєстраторів** заради більшої кількості спроб на секунду; при кількох претендентах домен іде на публічний аукціон ([DomCop guide](https://www.domcop.com/blog/guide-to-domain-drop-catching/)). Ловити преміум-домен вручну в 2026 неможливо.

## Частина 2. Спроєктований пайплайн

### 2.1. Головне архітектурне рішення

**Тут не потрібен агент. Потрібен ланцюг із двома LLM-викликами і детермінованим кодом посередині.**

Агент виправданий там, де крок неможливо визначити наперед. Тут усі кроки відомі. Агентна обгортка дала б +латентність, +вартість, +недетермінізм — без вигоди.

| Крок | AI чи код | Чому саме так |
|---|---|---|
| 1. Генерація кандидатів | **AI** | єдине місце, де потрібна мовна креативність |
| 2. Нормалізація й фільтр | **код** | довжина, дефіси, цифри, homoglyph, чорний список — це regex |
| 3. Перевірка доступності | **код** | детермінований факт. Модель тут = галюцинація |
| 4. Скоринг і шортліст | **AI** | субʼєктивна оцінка «звучить як бренд» |
| 5. Колізії бренду/соцхендли | **код + пошук** | детерміноване, але потребує зовнішнього джерела |
| 6. Дедуп і звіт | **код** | стан у SQLite/JSON |

**Червона лінія:** ніколи не питати модель «чи вільний домен X». Вона це вигадає. Доступність — тільки RDAP/DNS.

### 2.2. Кроки

```
[0] СТАН           domains.sqlite: seen(name, tld, status, checked_at, verdict)
                   Потрібен, щоб не показувати ті самі 40 назв щотижня.

[1] ГЕНЕРАЦІЯ      1 виклик Claude, structured output.
     ↓             Вхід: тема + стиль + СПИСОК УЖЕ ПОКАЗАНИХ (антидубль)
                   Вихід: JSON [{name, type: "brandable"|"keyword", rationale}]
                   ~120 кандидатів × 3 TLD = 360 доменів

[2] ФІЛЬТР (код)   довжина 5–14 · тільки [a-z] · без дефісів і цифр
     ↓             без homoglyph-пасток (rn/m, l/I) · не в чорному списку
                   вимовність: не більше 3 приголосних поспіль
                   → лишається ~90

[3] ДОСТУПНІСТЬ    ОСНОВНИЙ КАНАЛ: RDAP реєстру, 404 = вільний
     ↓             .com → rdap.verisign.com/com/v1/domain/{d}
                   інші → RDAP bootstrap з data.iana.org/rdap/dns.json
                   FALLBACK (коли RDAP закритий): сирий DNS NS на 2 резолвери,
                   NXDOMAIN на обох = ймовірно вільний
                   → ~30–50 «вільних»

[4] СКОРИНГ        1 виклик Claude лише по вільних.
     ↓             {"name":..., "pronounce":1-5, "memorable":1-5,
                    "spell_from_hearing":1-5, "brandable":1-5, "risk_note":"..."}
                   Сортування — код, не модель. Топ-10.

[5] КОЛІЗІЇ        для топ-10: пошук назви + соцхендли (github/x/instagram)
     ↓             цей крок відкинув 2 з 7 фіналістів у прогоні нижче — не пропускати

[6] ЗВІТ           Markdown + запис у стан. Показаний кандидат більше не зʼявиться повторно.
```

### 2.3. Промпт для кроку 1 (готовий до використання)

```

ПРАВИЛА ДЛЯ КОЖНОГО ІМЕНІ:
- 5–14 латинських літер, тільки [a-z], без дефісів, цифр, подвоєних слів
- вимовне з першого разу носієм англійської
- пишеться правильно, якщо почути вголос (тест «радіо»)
- не містить підрядком назву відомої компанії

СКЛАД НАБОРУ:
- 60 brandable: вигадані слова, 2-3 склади, без словникового кореня
```

### 2.5. Обробка збоїв

| Збій | Поведінка |
|---|---|
| RDAP таймаут/5xx | ретрай ×3 з backoff 1-2-4с, потім DNS-fallback з поміткою «слабкий метод» |
| RDAP rate-limit (429) | пауза за `Retry-After`, батчі по 20 з паузою 1с |
| DNS SERVFAIL | статус «НЕВИЗНАЧЕНО», ніколи не «вільний» |
| Модель повернула не-JSON | structured output + strict; 1 ретрай, потім явна помилка, не тихий порожній список |

## Частина 4. 5 кандидатів — з чесним статусом перевірки

### Метод перевірки

Сирий DNS-запит NS на **два незалежні резолвери** (8.8.8.8 і 1.1.1.1). `RCODE=3` (NXDOMAIN) на обох = імені немає в делегуванні. Час: 2026-08-03 21:07 UTC.
Контролі того самого прогону: `google.com` → `rc=0,an=4`; `perplexity.ai` → `rc=0,an=2`; `elevenlabs.io` → `rc=0,an=4` — усі коректно TAKEN.
Обсяг: 398 DNS-перевірок, 118 «FREE?».

### Межі методу — важливо

DNS NXDOMAIN — **сильний, але не остаточний** сигнал:
1. Зареєстрований домен без nameservers (щойно куплений, redemption/pendingDelete, clientHold) теж дає NXDOMAIN → хибний «вільний».
2. Registry-reserved і premium імена дають NXDOMAIN, але коштують у рази більше або недоступні. Для `.ai` це реальний ризик.
3. Юридичне підтвердження = RDAP реєстру або чек реєстратора. Обидва канали в цьому середовищі закриті (egress-блок, див. §5).

**Статус кожного домену нижче: «DNS-вільний, RDAP НЕ перевірено».** Перед покупкою — вбити назву в пошук реєстратора (30 секунд).

### Кандидати
Тема обрана нейтральною (AI-агенти / автономна робота / соло-фаундер), бо проєкт не привʼязаний до конкретного бізнесу.

**1. `orbvane` — brandable ⭐ топ-рекомендація**
`.com` · `.ai` · `.io` — усі DNS-вільні (`rc=3,an=0` на обох резолверах). 7 літер, 2 склади (`orb`+`vane`), вимовне з голосу. Пошук «Orbvane» — нуль збігів (тільки віддалено схожі Orbis/Orbcomm/Orbea, інші галузі). Найчистіший з пʼяти.

**2. `tanivor` — brandable**
Усі три TLD DNS-вільні. 7 літер, 3 склади, повністю вигадане слово. Пошук — нуль збігів. Мінус: довше вимовляти, `-vor` асоціюється з фармацевтикою.

**3. `solvarine` — brandable**
Усі три TLD DNS-вільні. 9 літер, асоціація з `solve`. **Попередження:** існує ірландський ювелірний бренд Solvar (з 1941), інша галузь, але звучання близьке.

**4. `staffofagents` — keyword**
Усі три TLD DNS-вільні. 13 літер, описове — «штат агентів», `.ai` пасує найкраще. Мінус: довге.

**5. `aistaffofone` — keyword**
Усі три TLD DNS-вільні. 12 літер, «AI staff of one». Мінус: на слух може розбитись як `a-i-staff`.

### Відкинуті кандидати (залишено видимими)

| Кандидат | DNS | Чому відкинуто |
|---|---|---|
| `workerroster.*` | усі вільні | плутається з активним брендом AgentRoster (agentroster.ai) |
| `cyprano.*` | усі вільні | зайняті соцхендли (instagram.com/cyprano — музикант) |
| `agentpayrollhq.*` | усі вільні | суфікс `hq` — ознака, що гарну назву вже зайняли |
| `obsidara.com`, `mirovane.com`, `evalops.io`, `digitalcoworkers.ai`, `lunaro.io` | SERVFAIL двічі поспіль | статус невизначений, НЕ подано як вільні |

**Спостереження:** з 60 імен першого батчу вільним у `.com` було рівно **одне**. У `.ai`/`.io` — десятки. Чистий `.com` у 2026 доводиться конструювати (довші неологізми), а не знаходити.

## Частина 5. Що перевірено · що припущення · чого не знаємо

### Перевірено власним виводом
- DNS-статус усіх 15 доменів на двох резолверах з контрольною групою в тому ж прогоні.
- Що `whois`, `dig`, `nslookup` відсутні в контейнері.
- Що RDAP-хости заблоковані egress-політикою (403 на CONNECT, підтверджено статусом проксі).
- Що UDP/53 перехоплюється — авторитетна перевірка на рівні реєстру неможлива в цьому середовищі.
- Що `.github/workflows/` у репозиторії немає.
- Що пошук не дає збігів на «Orbvane»/«Tanivor», і що AgentRoster та Solvar існують.

### Припущення
- Оцінка токенів (2500 in/2300 out) — прикидка, не вимір. Навіть за похибки ×2-3 висновок «дешево» не змінюється.
- Що `domain-search-mcp` працює як заявлено в README — не встановлювався й не тестувався.
- Що ці 15 доменів реально можна зареєструвати — DNS каже «делегування немає», не «реєстрація вільна» (різниця описана вище).
- Що Haiku 4.5 дасть достатню якість генерації — evals не прогонялись, це оцінка з характеру задачі.

### Не знаємо / не перевірено
- **Чи домени вільні за RDAP** — канал закритий. Це головна діра в перевірці.
- Чи вони premium/registry-reserved (особливо ризик для `.ai`).
- Ціна кожного домену в конкретного реєстратора (не перевірялось — і поза скоупом «нічого не купувати»).
- Торгові марки в реєстрах USPTO/EUIPO — робився лише веб-пошук, не пошук по реєстрах ТМ. **Це зона `legal-compliance`.**
- Чи `create_trigger` (Routines) доступний у цій сесії.
- Реальна якість Namelix / Instant Domain Search MCP — не тестувалась.

## Скрипт перевірки (для company/tools/, якщо рішення — будувати інструмент)

```python
#!/usr/bin/env python3
"""Етап-1 чекер доступності домену БЕЗ API-ключів і без whois/dig.
Метод: сирий DNS-запит (UDP/53) на два незалежні резолвери за записом NS.
  RCODE=3 (NXDOMAIN) на обох -> делегування немає -> ЙМОВІРНО ВІЛЬНИЙ
  RCODE=0 і є відповідь       -> делеговано       -> ТОЧНО ЗАЙНЯТИЙ
  інше / розбіжність          -> НЕВИЗНАЧЕНО
Обмеження: зареєстрований домен без NS (щойно куплений, redemption/pendingDelete,
clientHold) дає NXDOMAIN -> хибний "вільний"; registry-reserved/premium теж.
Остаточне підтвердження = RDAP реєстру або чек реєстратора."""
import socket, struct, random, sys, concurrent.futures as cf

RESOLVERS = ["8.8.8.8", "1.1.1.1"]
TIMEOUT, RETRIES = 5, 2

def dns_query(name, qtype, server):
    for _ in range(RETRIES):
        tid = random.randint(0, 65535)
        header = struct.pack(">HHHHHH", tid, 0x0100, 1, 0, 0, 0)
        qname = b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\x00"
        pkt = header + qname + struct.pack(">HH", qtype, 1)
        s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); s.settimeout(TIMEOUT)
        try:
            s.sendto(pkt, (server, 53))
            data, _ = s.recvfrom(4096)
            if struct.unpack(">H", data[:2])[0] != tid:
                continue
            flags = struct.unpack(">H", data[2:4])[0]
            return flags & 0xF, struct.unpack(">H", data[6:8])[0]
        except Exception:
            continue
        finally:
            s.close()
    return None, None

def verdict(domain):
    res = [(srv, *dns_query(domain, 2, srv)) for srv in RESOLVERS]  # 2 = NS
    rcodes = [r[1] for r in res]
    if all(rc == 3 for rc in rcodes):
        v = "FREE?"
    elif any(rc == 0 and an and an > 0 for _, rc, an in res):
        v = "TAKEN"
    elif any(rc is None for rc in rcodes):
        v = "NO-ANSWER"
    else:
        v = "UNCLEAR"
    return domain, v, res

def main():
    domains = [l.strip() for l in sys.stdin if l.strip() and not l.startswith("#")]
    with cf.ThreadPoolExecutor(max_workers=12) as ex:
        out = list(ex.map(verdict, domains))
    for d, v, res in sorted(out, key=lambda x: (x[1] != "FREE?", x[0])):
        detail = " ".join(f"{s}:rc={rc},an={an}" for s, rc, an in res)
        print(f"{v:9} {d:32} {detail}")

if __name__ == "__main__":
    main()
```
