# Як будуються сайти: розбір Manus / Kimi і наш конвеєр

## Що вони роблять насправді

Розбір на атоми. Секрет не в тому, що «AI малює сайт» — а в тому, що
**структура не вигадується щоразу заново**.

| Атом | Що це | Навіщо |
|---|---|---|
| 1. Бриф | текст або детальний опис | вхід |
| 2. **Вибір шаблону** | користувач тицяє один із готових | ← ключовий крок |
| 3. Контент-модель | бриф → структуровані слоти (не проза) | розділяє «що сказати» і «як показати» |
| 4. Підгонка | контент розкладається по слотах шаблону | результат передбачуваний |
| 5. Рендер | сучасний код, Tailwind-подібні утиліти, адаптив | |
| 6. Деплой | одразу живий URL | |
| 7. Правка розмовою | «зміни колір», «додай блок» — точково | не перегенерація всього |

Архітектура Manus: **Planner → Executor → Verifier**, паралельні під-агенти,
цикл виконання інструментів. Модель під капотом — Claude і донавчений Qwen.
Тобто модель та сама, що й у мене. **Різниця не в моделі, а в конвеєрі.**

### Чому їхній підхід дає стабільну якість
Генерація з нуля кожного разу = якість стрибає. Фіксований перевірений
кістяк + змінний контент і візуальна мова = якість передбачувана.
Це та сама причина, чому друкарня має макети, а не малює кожну листівку.

## Наш конвеєр — те саме, але з нашими правилами

```
БРИФ
  ↓
1. ДОШКА РЕФЕРЕНСІВ     render_board.py     ← 8 візуальних мов, власник обирає номер
  ↓
2. КОНТЕНТ-МОДЕЛЬ       content.json        ← слоти, а не проза
  ↓
3. ШАБЛОН СТРУКТУРИ     --template saas     ← фіксований порядок секцій
  ↓
4. РЕНДЕР               render_site.py      ← один HTML-файл, нуль зовнішніх запитів
  ↓
5. ПЕРЕВІРКА            Playwright          ← 1440 і 390, без JS, консоль
  ↓
6. ПРАВКА               редагуємо content.json і перегенеровуємо
```

### Команди

```bash
# 1. показати вибір
python3 .agents/skills/design-system/scripts/render_board.py \
    --headline "…" --product "…" --out board.png

# 2. побачити контент-модель
python3 .agents/skills/design-system/scripts/render_site.py --schema > content.json

# 3. зібрати
python3 .agents/skills/design-system/scripts/render_site.py content.json \
    --direction 2 --template saas --out index.html
```

### Шаблони структури

| Шаблон | Порядок секцій | Для чого |
|---|---|---|
| `saas` | hero · proof · problem · features · how · pricing · faq · final | підписка, продукт |
| `service` | hero · proof · problem · how · features · pricing · faq · final | послуга, агенція |
| `waitlist` | hero · problem · features · how · faq · final | до запуску, збір інтересу |
| `product` | hero · features · how · proof · pricing · final | коротка сторінка товару |

Порядок не випадковий: `problem` перед `features`, бо спершу впізнавання,
потім рішення. `pricing` перед `faq`, бо FAQ знімає заперечення щодо ціни.

### Що дає ця конструкція

- **Дошка і результат — одна мова.** `render_board.py` і `render_site.py`
  імпортують один `directions.py`. Що обрали — те й отримали.
- **Правка не ламає решту.** Змінюєте один слот у JSON — решта сторінки та сама.
- **Порожній слот видно.** Немає ціни в контент-моделі — секція просто не рендериться,
  замість того щоб я вигадав ціну.
- **Нуль зовнішніх запитів.** Системні шрифти, inline SVG. LCP швидкий, і сторінка
  перевіряється скріншотом тут же.

### Чого нам ще бракує проти Manus
1. **Візуал у герої.** У них праворуч мокап/ілюстрація, у нас поки порожньо —
   герой лівовирівняний і права половина не працює. Наступне доопрацювання.
2. **Деплой одним кроком.** У них одразу URL. У нас — файл, деплой руками
   (Vercel MCP закрив би це).
3. **Правка розмовою без перегенерації.** Поки редагуємо JSON.

**Висновок:** код для локальної генерації ставиться, **ваги моделей — ні**.
Це не моє обмеження і не брак варіантів: це політика вихідного трафіку
середовища, і README проксі прямо забороняє її обходити.

### Що це відмикає — одна дія власника
Дозволити в мережевій політиці середовища два хости:
```
huggingface.co
cdn-lfs.huggingface.co
```
Налаштування: https://code.claude.com/docs/en/claude-code-on-the-web

Після цього реалістично на CPU без GPU:

|---|---|---|---|
| SDXL-Turbo (1-4 кроки) | ~7 ГБ | 60-120 с | фони, текстури, абстракція |

| SDXL повний | ~7 ГБ | 5-10 хв | якісно, але повільно |

Тобто **фони й абстракція — так, потоково фотореалізм — ні** без GPU.

### Що працює вже зараз, без жодних дозволів

1. **Процедурна генерація растру** — Pillow + numpy встановлені. Градієнтні
   меші, шум, текстури, патерни, генеративна графіка. Для абстрактних
   фонів лендінга це часто краще за нейромережу: детерміновано, миттєво,
   під точні кольори бренду.
2. **Gamma MCP** — справжня AI-генерація (gpt-image-1, Flux 2, Ideogram,
   Recraft, Imagen 4). Обмеження: преміальні моделі вимагають плану Pro,
   і готовий файл забирає власник за посиланням.
3. **SVG** — іконки, ілюстрації, діаграми, логотипи. Малюю напряму.
